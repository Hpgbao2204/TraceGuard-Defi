# Execution-dependency protocol

The supplementary six-case round is not a causal-efficacy benchmark. Its
adjudicated records describe flash liquidity as enabling-only. A separate
dependency experiment may test whether neutralizing that primitive blocks the
observed execution path, without promoting the result to root cause.

Required gates before any verdict are B2 fidelity, preregistered primitive and
site, verified application and semantic contract, expected boundary, and an
executable sham control. Outcomes are `DEPENDENCY_CONFIRMED`,
`DEPENDENCY_NOT_CONFIRMED`, or `INCONCLUSIVE`. The matrix in
`eval/results/m6_dependency_operator_matrix.json` is the frozen D2 boundary
manifest. Four cases have exact provider frames and callback boundaries and
are replay-authorized; all outcomes remain dependency outcomes, never CAUSE.
